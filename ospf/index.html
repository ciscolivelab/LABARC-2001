    Localized Policy - OSPF

    Task 1: OSPF Policy

    In this task, you will configure a localized control policy on the SD-WAN Edge router to advertise OSPF routes into the SD-WAN overlay.

    🛠 Set OSPF Metric

    Log in to SD-WAN Manager from your browser with:

    • Username: admin
    • Password: C1sco12345

    Step 1

    In Site 300, OSPF is pre-configured between core router Site300-Core-VPN10 and Site300-cE1 on the service side. Mutual redistribution between OMP and OSPF is also enabled.

    Step 2

    Verify the OSPF neighbor:

    • Navigate to Monitor > Devices > Site300-cE1 > Real Time > OSPF Neighbors

    Step 3

    Verify the local route 131.131.131.0/24 is installed as an OSPF route in the VPN 10 routing table:

    • Navigate to Monitor > Devices > Site300-cE1 > Real Time > IP Route

    Step 4

    Verify the OMP route 131.131.131.0/24 is installed at the remote site:

    • Navigate to Monitor > Devices > Site400-cE1 > Real Time > IP Route

    Step 5

    Verify OMP routes are being redistributed into OSPF and installed on Site300-Core-VPN10:

    1. Open mRemoteNG from the jumphost desktop

    2. Select Site300-Core-VPN10 from the pre-configured PuTTY session

    💡 Note: If you don’t see pre-configured connections, check View > Connections

    1. Log in with:
    2. Username: cisco

    3. Password: cisco

    4. Run the command: show ip route

    ✅ Note: Redistributed routes appear as E2 routes with a default metric.

    ➕ Add Route Policy to Set OSPF Metric (1000)

    Step 6

    1. Navigate to Configuration > Policies > Custom Options > Localized Policy > Route Policy

    2. VIP18-Route-Policy is pre-configured to set OSPF metric to 1000. Click ... to view the policy details.

    3. To attach the route policy:

    4. Navigate to Configuration > Policies > Localized Policy

    5. Select pre-configured policy Site300-Local-Policy-v1

    6. Click ... > Edit

    7. Select Route Policy > Add Route Policy > Import Existing

    8. Select VIP18-Route-Policy from the Policy drop-down, then click Import

    9. Click Save Policy Changes to push configuration Site300-cE1-v1

    10. Apply the Route Policy to OSPF:

    11. Navigate to Configuration > Templates > Feature Templates

    12. Search for VIP18-OSPF-Neighbor and select Edit
    13. Under REDISTRIBUTE, click the pencil icon to edit omp redistribution
    14. In Route Policy, select Global, and configure VIP18-Route-Policy

    ⚠️ Note: Make sure to enter the name exactly as shown.

    1. Save the template changes and push the configuration to Site300-cE1

    2. Log in to Site300-Core-VPN10 again (Username: cisco, Password: cisco) and run: show ip route

    ✅ Note: OSPF E2 route now has metric 1000

    🚫 Block Default Route on Service Side

    Currently, Site300-Core-VPN10 is incorrectly advertising a default route to Site300-cE1.

    You’ll now block this using a Route Policy.

    Step 7

    1. Navigate to Configuration > Policies > Custom Options > Localized Policy > Route Policy

    2. Click Add Route Policy

    3. Create a new route policy named OSPF-LAN with two sequence rules:

    4. Sequence 1: Match Address = default, Action = Reject

    5. Sequence 2: Match Everything, Action = Accept

    6. Attach the OSPF-LAN route policy:

    7. Navigate to Configuration > Policies > Localized Policy

    8. Select pre-configured policy Site300-Local-Policy-v1
    9. Click ... > Edit
    10. Select Route Policy > Add Route Policy > Import Existing

    11. Choose OSPF-LAN from the drop-down and click Import

    12. Click Save Policy Changes to push configuration to Site300-cE1-v1

    ⏳ Note: Wait until configuration push completes

    1. Apply the Route Policy to OSPF:

    2. Navigate to Configuration > Templates > Feature Templates

    3. Search for VIP18-OSPF-Neighbor and click Edit
    4. Under ADVANCED, set Policy Name (Global) to OSPF-LAN

    ⚠️ Note: Make sure to enter the name exactly

    1. Save the template and push the configuration to Site300-cE1

    2. Verify the default route is now blocked:

    3. Navigate to Monitor > Devices > Site300-cE1 > Real Time > IP Route

    ❓ Question to Think About

    Can you think of alternate options to prevent the default route from being advertised to OMP?
